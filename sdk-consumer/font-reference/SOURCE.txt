Comparator:
  Public Page.evaluate replaces the already-verified original fixture with a
  192px regular text row and an independent SVG path row. Screenshot ink is
  thresholded at 160, translated to its bounding-box origin (never resized),
  then compared bidirectionally. Every ink pixel must have matching ink within
  one CSS pixel (ceil(device scale)); unrelated interior ink cannot be ignored.
  This is a deliberately strict geometric edge tolerance, NOT a calibrated
  cross-platform golden. Main must run positive/negative GNU/Alpine x64/ARM64
  cases before claiming platform acceptance. If correct-font rasterization
  exceeds it, inspect the saved evidence and measured unmatched pixel counts;
  do not replace the fixed oracle with runtime output or silently loosen it.
  MOLI_SDK_EVIDENCE_DIR stores font-reference.png and geometry before assertion.

Linux procedure (requires fontconfig tools and already-built real consumer):
1. Download the pinned fonts above during environment preparation; verify the
   listed SHA-256 before use. Keep them outside the SDK/package. Obtain fixed
   DejaVu Sans 2.37 as for the existing Latin acceptance.
2. Create separate isolated directories /tmp/sdk-font-positive and
   /tmp/sdk-font-negative. Put DejaVuSans.ttf in both. Put ONLY the pinned Sans
   OTF in positive and ONLY the pinned Serif OTF in negative. Do not include
   global Fontconfig configs, which could rediscover system Sans fonts.
3. Create two Fontconfig files from this template, replacing CASE with positive
   or negative. The alias is needed only in the negative config:

<?xml version="1.0"?>
<!DOCTYPE fontconfig SYSTEM "urn:fontconfig:fonts.dtd">
<fontconfig>
  <dir>/tmp/sdk-font-CASE</dir>
  <cachedir>/tmp/sdk-font-cache-CASE</cachedir>
  <alias binding="strong"><family>Noto Sans CJK SC</family><prefer><family>Noto Serif CJK SC</family></prefer></alias>
</fontconfig>

4. FONTCONFIG_FILE=/tmp/positive.conf fc-match 'Noto Sans CJK SC'
   FONTCONFIG_FILE=/tmp/negative.conf fc-match 'Noto Sans CJK SC'
   Require Sans then Serif respectively (and DejaVu Sans for the Latin family).
   fc-match is a prerequisite diagnostic, not acceptance by itself.
5. Run the built consumer in fresh processes:
   FONTCONFIG_FILE=/tmp/positive.conf MOLI_SDK_EVIDENCE_DIR=/tmp/font-positive ./moli-sdk-consumer fonts
   FONTCONFIG_FILE=/tmp/negative.conf MOLI_SDK_EVIDENCE_DIR=/tmp/font-negative ./moli-sdk-consumer fonts
   Require positive exit 0 / matches=true and negative nonzero / matches=false.
   Preserve stderr plus both evidence directories. Repeat on GNU and Alpine,
   both architectures; do not report these runs as completed from extraction.
