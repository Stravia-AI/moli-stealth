# 以现有 ChromeTransport 替代 curl，默认不退化网络能力

深化现有 ChromeTransport 并最终删除 curl，选择保持现有对外网络能力的迁移，而非通过收缩产品能力加速删除依赖。并发、真实流式、取消和资源限制纳入替代验收；任何能力删除或不兼容变化必须逐项确认，不得静默降级，也不要求照搬 curl 特有实现或既有错误行为。

## 传输库定位

替代实现定位为类似 curl 的底层传输库，而不是固定绑定 Chrome 身份的浏览器网络策略层。底层库不主动启用 stealth，Moli 默认显式启用内置伪装配置，用户可以关闭或自定义，以区分通用传输能力与 Moli 的产品默认行为。

“类 curl”指同类传输能力，不要求 libcurl API/ABI 或 easy/multi 调用模型兼容。底层采用原生 Rust async 请求与增量响应体接口，内部管理连接复用和协议；Moli 现有同步入口通过同一实现的薄封装保留，不维护另一套同步传输栈。

## 联动配置与显式覆盖

自定义范围包括传输指纹与浏览器身份联动：系统级配置协调 TLS/HTTP 指纹、UA、Client Hints 和 JavaScript 可见身份，复用并整合现有身份模型，不另建一套独立身份来源。提供内置联动预设，并允许显式覆盖 TLS/HTTP 底层参数及身份字段；校验参数合法性和明确可检查的一致性约束，不保证任意自定义组合等同于真实浏览器。本次不扩展屏幕、GPU、Canvas 或音频伪装。

联动配置提供一致的身份与传输基线，已有自动化接口的显式 UA/身份覆盖优先，并保留原接口语义，不根据 UA 猜测或自动替换 TLS/HTTP 指纹。这类覆盖可能使身份与传输不一致，调用方需要另行指定相应传输配置，而不是由系统拒绝既有任意 UA 定制能力。

stealth 开关与整套联动配置仅在进程级设置，每个 Moli 进程使用一套配置；启动时加载并固定，修改开关、预设或底层参数需要重启，不提供运行时整套配置切换，以避免旧连接指纹与新身份混用。不同完整配置通过不同进程运行，既有运行时及页面 UA/身份覆盖仍保留，但不新增 BrowserContext 或页面 target 级 stealth 开关和整套配置覆盖。

## 协议范围

本次同时迁移页面发起的 WS/WSS 建连，使其连接、代理、TLS 和 HTTP Upgrade 所需传输机制使用同一底层能力与 stealth 配置，避免 HTTPS 与 WSS 各用一套指纹配置。保留现有 WebSocket 帧协议和浏览器事件处理，不改入站 CDP/WebDriver 服务。

本次不要求新增 HTTP/3，交付聚焦现有 HTTP/HTTPS 能力、HTTP/1.x 与 HTTP/2 及出站 WS/WSS 迁移；未接入的 QUIC/H3 实现不计为已支持功能，也不为未来 H3 预造接口。

## 维护与验收

现有导入传输代码转为 Moli 自主维护，不再以保持 BrowserOxide 源码形状及整体同步便利为目标。复用可用实现和依赖，允许围绕新职责重组并删除不再使用的导入逻辑；保留来源与许可证，上游修复按需移植，不为同步保留多余接口。

完成标准采用受控本地环境中的真实浏览器对照及现有功能契约不退化，不以第三方网站放行为保证。内置预设绑定明确的参考浏览器版本，对照实际 TLS/HTTP 特征、HTTPS/WSS 建连和身份表面，并覆盖新建及复用连接；随机字段按语义规则比较，不只校验参数常量或 JA3/JA4。自定义配置验证明确参数的实际效果，不保证任意组合对应真实浏览器。
