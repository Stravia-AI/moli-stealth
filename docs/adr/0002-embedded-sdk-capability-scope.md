# 嵌入式 SDK 提供通用能力，以现有宿主用法作为最低验收范围

为减少 Rust 宿主日常开发时重复编译 Moli 的成本，计划提供预编译静态库及 Rust SDK。SDK 的能力范围选择通用嵌入式接口，以 StraviaPlatform 当前的浏览器、页面、JavaScript 求值、独立 HTTP 传输及 Cookie 用法作为最低验收范围，而非只提供面向 Stravia 的 HTML 获取接口，也不完整镜像 Moli 内部公共 Rust API。

该选择避免将正文抽取、搜索就绪条件和公网地址策略固化到 Moli 中，同时控制长期接口维护成本。迁移不得丢失现有调用所依赖的固定解析地址、显式禁用代理绕过、增量响应读取、超时、取消和资源回收语义。

## 静态链接范围

Moli Rust 实现及 V8、TLS 等所需非系统依赖采用预编译静态链接，宿主无需编译这些源码，运行时也无需另带这些依赖的动态库。允许依赖目标操作系统的系统库、系统框架及约定的运行库，不要求最终宿主程序完全静态。该选择聚焦日常编译成本，不额外引入跨平台完全静态部署约束；具体运行库和最低系统版本需按目标平台确定。

## SDK 发布平台

首批 SDK 预编译产物覆盖 Windows MSVC、Linux GNU 和 Linux musl，各自支持 x86_64 与 ARM64，共六个 Rust target：

- `x86_64-pc-windows-msvc`
- `aarch64-pc-windows-msvc`
- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`
- `x86_64-unknown-linux-musl`
- `aarch64-unknown-linux-musl`

macOS 不在本次 SDK 发布范围内，此决定不删除现有 CLI 的 macOS 发布能力。musl 是新增的 SDK 交付要求，不代表现有依赖已经具备可直接复用的兼容产物；需要验证包含 V8 在内的完整静态依赖链和实际宿主运行。

## 运行时所有权

预编译库内部管理 Moli 所需的所有者线程和异步运行时，负责浏览器与页面的创建、执行、取消和销毁；Rust SDK 对宿主提供异步接口，不要求宿主创建 Moli 专用线程或显式驱动事件循环。该选择将线程亲和性和资源回收约束留在实现侧，以内部调度和跨线程通信成本换取宿主集成简单性。

FFI 不传递 Rust `Future`、Tokio runtime 或内部 Rust 对象，避免让宿主与预编译实现依赖相同的 Rust 类型布局和 Tokio 版本。具体任务通知机制仍待设计。

## 显式异步关闭与非阻塞析构

丢弃操作 Future 时请求取消，由内部完成必要回收，取消后不得访问已释放的宿主数据。显式 `close().await` 取消所属在途操作并等待所属资源回收完成，关闭失败通过错误返回。未显式关闭而直接 `Drop` 时提交取消及回收，不阻塞宿主线程，也不保证析构返回时回收已经完成。

最后一个外部句柄释放后，内部仍须完成清理，不能因通知接收端消失而泄漏资源。该选择将确定的回收完成保证放在显式异步关闭上，避免在宿主异步执行线程或回调中引入隐藏的阻塞析构和死锁风险。

## SDK 与预编译产物精确绑定

每个 SDK 版本固定预编译产物的 GitHub Release 标识、各 target 的产物名和 SHA-256，不自动选择 `latest` 或所谓兼容的较新实现。`build.rs` 优先复用校验通过的本地缓存，缓存缺失时下载固定产物；下载失败或校验失败明确报错，不自动回退源码编译。该选择以升级实现时同步更新 SDK 绑定的成本，换取可复现的产物选择及可解释的构建失败。

提供显式本地产物路径供离线构建和 Moli 本身开发使用。SDK 绑定的摘要来自 SDK 发布内容，不以下载时从同一 Release 临时读取的摘要替代固定绑定。

默认下载及缓存严格匹配固定 Release 和 SHA-256；显式本地覆盖允许尚未发布、实现内容不同的构建，但必须携带产物清单，通过文件完整性、target、CRT 等链接条件及内部 ABI 身份校验。ABI 不匹配时拒绝使用，要求同步更新 SDK，不提供跳过 ABI 校验的入口。本地产物及清单由开发者显式信任，其中的摘要只验证完整性，不证明来源可信。

## 单套完整产物

每个 target 发布一套完整静态产物，通过一个 Rust SDK 提供浏览器、独立 HTTP 传输和 Cookie 能力，不另建轻量网络产物。该选择匹配 StraviaPlatform 同时使用两组能力的现状，避免维护两套分发矩阵及其公共静态实现的重复链接问题。

仅使用 HTTP 不启动浏览器，但仍需下载完整产物；最终宿主可裁剪掉多少未使用代码，以实际链接结果为准，不承诺剔除全部 V8 代码。本决定不要求所有静态依赖物理合并成单个归档文件。

## C ABI 仅作为 SDK 内部连接层

对外承诺 Rust SDK 的公共接口，C ABI 仅连接 SDK 与精确绑定的预编译实现。该连接层使用明确的 C 调用约定、不透明句柄及内存所有权规则，不传递内部 Rust 对象；不承诺跨版本头文件与静态库混用，也不同时提供面向其他语言的公共 C ABI 及其兼容矩阵。

该选择与精确产物绑定一致，避免为当前未要求的多语言接入承担长期 ABI 兼容成本。内部连接层仍需防止版本不匹配造成未定义行为；具体身份校验及错误报告方式待设计。

## Windows 使用静态 CRT

Windows x86_64 和 ARM64 仅提供静态 MSVC CRT 产物，要求宿主为对应 target 启用 `+crt-static`，使 Rust 与原生依赖的 CRT 选择一致。SDK 的 `build.rs` 检查目标配置，不满足要求时明确报错并给出配置指引，不尝试替宿主或其他依赖修改编译选项。

该选择沿用现有 V8 静态 CRT 构建方向；StraviaPlatform 已为两个 Windows target 配置 `+crt-static`。不新增动态 CRT 产物及其原生依赖验证矩阵，依赖仓库内的 Cargo 配置也不视为宿主自动获得的配置。

## Linux GNU 兼容基线

Linux GNU 的 x86_64 和 ARM64 产物以 Debian 12 为最低验证基线，与现有 Moli 的 Bookworm 发布构建环境及 StraviaPlatform 的 Docker 运行环境一致。两种架构均需在该基线上运行实际链接 SDK 的宿主程序，验证完整依赖链，而非仅检查构建成功。

其他 GNU/Linux 发行版按实际运行库要求判断兼容性，不按发行时间推断支持；本次不承诺 Debian 11、Ubuntu 22.04 等更老基线。该决定不适用于独立的 Linux musl 产物。

## musl 不要求完全静态宿主

Linux musl 产物的使用目标是在 Alpine 等 musl 系统上运行，x86_64 和 ARM64 均需验证。允许依赖 musl 环境中的动态库，不以最小宿主没有任何动态库依赖作为交付要求，也不因选择 musl target 就额外要求宿主启用静态 CRT。允许动态链接并不等于必须动态链接；验收以宿主在目标系统实际运行及依赖完整为准。

这一目标不撤销此前确认的 Moli 及非系统依赖静态分发契约，不据此扩大为要求宿主自行安装 V8、TLS、Fontconfig 等非系统动态库。部署时仍需满足实际系统运行库和运行时数据要求，具体依赖清单需由链接与运行验证确定。

Alpine 3.23 是 x86_64 和 ARM64 的最低验证版本，沿用 StraviaPlatform 现有 musl 原生依赖准备环境。必须在该版本的运行容器中验证实际宿主链接、字体加载及页面渲染，不以构建阶段使用 Alpine 3.23 代替运行验证，也不据此承诺更老版本兼容。

## Alpine 字体加载与渲染验收

Alpine 支持必须包含正确加载渲染所需字体，不能仅以程序启动、HTML 获取或 JavaScript 执行成功作为验收。两个架构都需在受控字体环境中验证实际字体选择及文本布局、渲染结果，不能仅凭截图文件生成成功判断字体可用。

字体文件及 Fontconfig 配置由部署环境提供，SDK 正确发现并使用系统字体，不内置或另行分发基线字体包。Alpine 部署文档需明确字体及配置的安装要求，发布验证固定字体环境，覆盖中文、拉丁文字、字体回退和实际渲染。

静态链接字体相关原生库不等于携带字体文件及 Fontconfig 配置；不将 GitHub Actions 构建机的字体环境或路径视为宿主运行时字体环境，也不承诺未安装字体的空白 Alpine 镜像可正常渲染所有文字。此决定不放宽此前非系统原生依赖静态链接的要求。

## 宿主各构建 profile 共用优化产物

宿主的 debug 和 release 构建链接同一套优化后的 Moli 静态产物，不按宿主 Cargo profile 发布另一套 debug 实现。另行分发与产物匹配的调试符号，按需获取；深入调试 Moli 时使用显式本地构建产物。

该选择减少 profile 切换带来的额外下载、缓存及发布矩阵，聚焦宿主的日常开发速度。调试符号不消除优化对单步执行和局部变量查看的影响，不承诺预编译实现具有未优化构建的调试体验。

## SDK 通过当前仓库的 Git revision 分发

当前仓库提供独立 Rust SDK crate，宿主通过精确 Git revision 引用，沿用 StraviaPlatform 现有的依赖获取方式。本次不包含 crates.io 发布。

SDK 的依赖图不得直接或间接引入 `moli-core` 等 Moli 源码实现 crate，仅包含 Rust 封装、内部 FFI 声明、下载校验和链接所需逻辑及轻量依赖。该选择保留 Cargo 获取 Git 仓库的检出成本，但避免日常宿主构建重新编译 Moli 实现，也不新增 crate registry 发布流程。

## 公共 SDK 消费接缝验收

以仓库外真实 Rust SDK 消费项目作为主验收接缝，项目只依赖 SDK 和实际预编译产物，不直接引用 Moli 源码实现。通过同一消费入口验证下载与链接、运行行为、六平台兼容、字体渲染及日常构建成本；复用已有受控服务器和页面 fixture，不以内部 FFI 调用次数或线程结构代替外部行为验收。

完整范围与验收要求见[功能规格](../../.scratch/precompiled-rust-sdk/spec.md)。内部符号、通知机制和清单字段等实现细节在已确认契约内设计，不再视为待确认的产品范围。
